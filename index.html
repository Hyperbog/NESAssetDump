NES Asset Ripper — Godot Edition

Offline desktop app for 8×8 NES graphics extraction and Godot-ready assets. Load ROMs or ZIP collections; no emulator or account required.

1. Game library

Drag files here to add them to your library. ZIP files are decompressed locally. Batch export can process the whole collection.
Open a ROM or a ZIP containing .nes games to begin.

2. Graphics

CHR-ROM gives exact tiles. For CHR-RAM games, a raw PRG scan is exploratory and may not reveal compressed assets.

3. Palette variants

A ROM tile does not encode its color palette or sprite identity.

16-byte or 32-byte NES palette indices, or 192-byte 64×RGB master palette.
0 manually assigned tiles
PRG palette candidates are unverified. Raw .pal export is available only for a selected 16/32-byte palette set. All exports retain provenance; PNG/CSV RGB values are approximate reference colors.

4. Atlas preview

Click a tile to inspect its original bytes. Enable palette assignment above to associate a sub-palette.

No tile selected.

5. Sprite assembly & animation

Manual sprite reconstruction: select any tile in the atlas, then click a cell below to place it. Right-click a cell to erase it. Palette group is stored per placed tile, but does not imply an original in-game association.

Click to place selected tile · Right-click to erase. Changing grid size resets frames.

Godot export includes all named animations with separate FPS and looping settings in a single SpriteFrames .tres, PNG sheet, AnimatedSprite2D .tscn, and editable project JSON. Extract the nes_assets/ folder into the root of your Godot project.

6. Export for Godot

PNGs are native-resolution with 8×8 tile alignment, no spacing or filtering. CHR-ROM raw extraction is exact; PRG scans are not confirmed game graphics. NES RGB colors are a reference approximation.

7. Unique 8×8 tile atlas

Find exact duplicate 16-byte tile patterns in the selected bank or entire source. The export keeps the first occurrence of every distinct tile and a complete lookup from original tile indices to unique atlas positions. Duplicates are based on original tile bytes, not display colors.

Load a ROM to analyze tile patterns.

Export includes native-resolution unique_tiles.png, exact tile-pattern bytes, and a JSON index mapping every original tile to its unique atlas entry. The PNG uses the selected palette group as a preview; per-tile manual palette assignments are preserved in JSON.

8. Searchable tile catalog & Godot TileSet

Search across all tiles in the selected graphics source by absolute tile index or original raw bytes. Browse the results without changing the source bank. Filters and exported TileSets retain original ROM offsets.

Load a ROM to browse tiles.

The TileSet includes a PNG atlas, a Godot 4 TileSet .tres with individually registered 8×8 tiles, and JSON mapping every selected atlas position to the original tile and bank. Optional manual palette assignments color each exported tile; original runtime assignments are not inferred.

9. Batch export NES collection

Export exact CHR-ROM tile banks from every loaded NES game in a single ZIP. Games with CHR-RAM are reported rather than misrepresented as raw graphics. No emulator setup required.

Load a collection ZIP or multiple NES ROMs to enable batch export.

Outputs a game-specific directory containing 8×8 bank PNG atlases, original CHR-ROM bytes, and tile-offset JSON. The ZIP includes a compatibility CSV showing games that need a CHR-RAM decoder. PNG colors are grayscale previews, not confirmed game palettes.

Godot 4 setup

Set texture filtering to Nearest. Use TileSetAtlasSource with texture_region_size = (8, 8), margins = (0, 0), and separation = (0, 0). For Sprite2D, enable regions; for AnimatedSprite2D, import frames from a sprite sheet.

Palette colors depend on game runtime state. Accurate sprite-palette association cannot be determined from CHR-ROM alone, although imported palette sets and manual associations can be preserved.
